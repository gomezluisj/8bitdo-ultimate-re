# Diagnóstico v17 y Especificación exacta de v18 (fw 1.11, 80NA)

## 1. Evidencia de captura BLE sobre `fw111_v17.bin`

- `+6.110s .. +7.943s`: anuncia `80NA    ` (`id=50810697`).
- `+8.207s .. +9.082s`: burst `"HH      "` (`id=F94C52DE`, payload `53050100037e056620000181<CONSOLE_MAC_6B>0f...`) de **solo `0.875 s`** (cortado antes de `WINDOW_MS=3000`).
- `9.87 s` sin BLE (`+9.082s .. +18.952s`).
- `+18.952s`: reaparece `80NA    `.
- `+19.231s .. +21.969s`: segundo burst `"HH      "` de **`2.738 s`** (`~WINDOW_MS=3000`).
- `9.27 s` sin BLE (`+21.969s .. +31.242s`); `+31.242s`: reaparece `80NA    ` sin haber conectado con Switch 2.

## 2. Causas raíz verificadas en `backups/pre-flash-stock-v2.bin`

1. **Corte prematuro del burst `"HH"` (`0.875 s`):**
   - `BT_CreatBtReconnect` (`0x01025D04`, únicos llamadores `0x0101C1AA` y `0x0101A386`) configura `page_timeout=0x12c0` (`4800` slots = `3.0 s`), `[0x000201e8] |= 0x80` y arma el timer `0x01025E41` de `6000 ms` (`0x1770`).
   - En el callback `0x01025E40..0x01025E88`, cuando `[0x000201aa] == 0` y `0x01023F40() == 0`, la instrucción **`0x01025E76`** llama a `0x0101BB5C(r0)` (`ldrb r0, [0x000201aa]`) *antes* de alcanzar `0x01025E82` (`fn_timer_guard` de `v17`). Además `v17` no cancela el timer (`0x0101DD44`) al entrar a `fn_on_shake`.
   - En paralelo, `0x01021A3A` enciende `[0x0002057e] = 1` antes de `0x01021A3E`. Si entra `HCI_EVENT_BT_BASEBAND_CONNECT` (`0x0101A2AC`), `0x0101A2C4` lee `[0x0002057e]` vía `0x0101E998()` y si es `!= 0` ejecuta `0x010191F0` en `0x0101A2E2` (Switch-1 wake, apaga BLE), limpia `[0x0002057e]=0` y reinicia directo vía `0x01026358` sin `0x20220228`.
   - Nota: mantener `[0x0002057e] == 1` durante `"HH"` sigue siendo necesario porque `0x01021A48` lo exige para ejecutar `0x01021A6A` (`fn_on_tick`) y porque `0x0101A314` (`HCI_EVENT_BT_RECONNECT_FAIL`) evita apagar BLE vía `0x0101A356`.

2. **Falta de reconexión Classic BT después de terminar `"HH"`:**
   - Al vencer `WINDOW_MS=3000`, `fn_on_tick` en `build_v17.py` llama a `ADDR_RADIO_CFG(0,0,0)` (`0x0101AF70`) y luego a `0x01026358` (`ADDR_RESET_CLEAN`) directamente.
   - Al arrancar tras un reset, `0x0101D4A0..0x0101D4DC` solo enciende el bit `1 << 20` en `[0x000201b4]` (vía `0x01026E98`) si `0x010253E6()` detecta encendido físico o si **`[0x0002fff4] == 0x20220228`** (`0x0101D4BE`).
   - Luego `0x01022018..0x01022040` llama a `0x01024040()` (checa bit `1 << 20`); solo si está en `1` llama a `0x0101C180()` -> `BT_CreatBtReconnect` (`0x01025D04`).
   - **`0x0101BB5C(0)`** sí escribe `[0x0002fff4] = 0x20220228` (`0x01026FC4`) antes de llamar a `0x01026358`; llamar `0x01026358` solo deja ese marcador apagado en reinicios desatendidos y no lanza `BT_CreatBtReconnect`.
   - El encendido de BLE de stock (`80NA`) ocurre en `0x0101B618 -> 0x0101B64C -> 0x0101B860 -> 0x0101B880 -> 0x0101B368 -> 0x0101AF70(0,0,1)`, lo que explica la demora inicial (`~6 s`) y las pausas de `~9 s` entre reinicios.

## 3. Especificación exacta de `v18` (`build_v18.py`)

Base: `backups/pre-flash-stock-v2.bin` (`131072` bytes, base `0x01018000`).  
Cave: `BASE = 0x01031A00`.  
RAM de estado: `STATE_RAM = 0x00026000` (`[0] = start_tick`, `[4] = armed_magic`), `ARMED_MAGIC = 0x56313801`, `WINDOW_MS = 4000`.

### Símbolos nuevos en `pre-flash-stock-v2.bin` (sumados a los de `build_v17.py`)
- `ADDR_RESET_20220228 = 0x0101BB5C` (`r0` = modo, `0` en Switch)
- `ADDR_TIMER_CANCEL   = 0x0101DD44` (void)
- `ADDR_GET_WAKEUP_FLAG = 0x0101E998` (retorna `r0 = [0x0002057e]`)
- `ADDR_SET_WAKEUP_FLAG = 0x010271C0` (`[0x0002057e] = r0`)

### Helper compartido de cierre (`fn_finish_wake`)
Con `r4 = STATE_RAM` (o cargado dentro):
1. `[STATE_RAM + 4] = 0` (`ARMED_MAGIC = 0`).
2. `ADDR_SET_WAKEUP_FLAG(0)` (`0x010271C0`).
3. `ADDR_RADIO_CFG(0, 0, 0)` (`0x0101AF70`).
4. `ADDR_RESET_20220228(0)` (`0x0101BB5C`, escribe `0x20220228` y ejecuta `0x01026358`).

### 6 hooks exactos (validar instrucción original exacta antes de parchar; mantener `0x0101B880 -> BL 0x0101B368` stock)
1. **`0x01021A3E` (`BL 0x010191F0`) -> `fn_on_shake`**:
   - Primero llama a `ADDR_TIMER_CANCEL()` (`0x0101DD44`).
   - Luego repite payload/MAC/`"HH"`/`op 0x34 ch 0x15` + `ADDR_RADIO_CFG(0,0,1)` de `v17` y guarda `start_tick` + `ARMED_MAGIC`.
2. **`0x01021A6A` (`BL 0x01026E4C`) -> `fn_on_tick`**:
   - Llama `ADDR_LED_TOGGLE(r0)`.
   - Si armado y `GET_TICK() - start_tick >= WINDOW_MS`: ejecuta `fn_finish_wake`.
3. **`0x01025E76` (`BL 0x0101BB5C`) -> `fn_timer_guard_early`**:
   - Preserva `r0` entrante (`[0x000201aa]`).
   - Si NO armado: restaura `r0` y llama `ADDR_RESET_20220228(r0)`.
   - Si armado y `< WINDOW_MS`: retorna sin reiniciar.
   - Si armado y `>= WINDOW_MS`: ejecuta `fn_finish_wake`.
4. **`0x01025E82` (`BL 0x01026358`) -> `fn_timer_guard_late`**:
   - Si NO armado: llama `ADDR_RESET_CLEAN()`.
   - Si armado y `< WINDOW_MS`: retorna sin reiniciar.
   - Si armado y `>= WINDOW_MS`: ejecuta `fn_finish_wake`.
5. **`0x0101A2C4` (`BL 0x0101E998`) -> `fn_bb_guard`**:
   - Si armado y `GET_TICK() - start_tick < WINDOW_MS`: retorna `r0 = 0` (evita `0x010191F0` y `0x01026358` sin `0x20220228` mientras corre `"HH"`).
   - Si armado pero `>= WINDOW_MS` (stale): limpia `[STATE_RAM + 4] = 0` y delega a `ADDR_GET_WAKEUP_FLAG()`.
   - Si NO armado: delega directo a `ADDR_GET_WAKEUP_FLAG()`.
6. **`0x0101A526` (`BL 0x0102C2FC`) -> `fn_hid_connect`**:
   - Llama `ADDR_HID_CB()` (retorno en `r0` no se usa; `0x0101A52A` hace `movs r0, #2`).
   - Si armado: desarma (`ARMED_MAGIC = 0`), llama `ADDR_SET_WAKEUP_FLAG(0)` y `ADDR_RADIO_CFG(0,0,0)`.

## 4. Comandos para generar, verificar y flashear (después de `/compact`)

1. Generar binario + desensamblar la zona parcheada y validar:
   - `python3 8bitdo-ultimate-re/build_v18.py` -> `8bitdo-ultimate-re/fw111_v18.bin`
2. Cifrar y verificar roundtrip contra `8cryptdo.py`:
   - `python3 8bitdo-ultimate-re/8cryptdo.py encrypt 8bitdo-ultimate-re/fw111_v18.bin -c yichip -v 111 -a 0x01018000 -o 8bitdo-ultimate-re/v18_enc.dat`
   - Extraer `v18_enc_body.bin = raw[28:]` (131072 bytes) y verificar descifrado idéntico byte a byte con `fw111_v18.bin`.
3. Flashear (control ya detectado en Boot mode `VID 2dc8 PID 3208 "8BitDo Boot"`, `main=111 beta=0`):
   - `./8bitdo-ultimate-re/boot/boot_macos flashe 8bitdo-ultimate-re/v18_enc_body.bin 8bitdo-ultimate-re/fw111_v18.bin`
